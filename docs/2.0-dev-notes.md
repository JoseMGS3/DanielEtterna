# DanielEtterna 2.0 development — chart normalization

This branch starts from the current main branch. Its first milestone only
prepares chart input for XDC1. The 1.1.1 runtime and calculator have **not**
been replaced; the app is still labeled 1.1.1 until the full migration.

## Common note format

New API in src/chart_loader.py:

    data = chart_loader.load_chart_file(path)
    selected = ...  # existing UI chart selection for .sm/.ssc
    notes = chart_loader.normalize_chart_notes(data, selected)
    rated_notes = chart_loader.rate_normalized_notes(
        notes, rate=1.25, include_long_notes=True
    )

For .osu, omit the selected chart argument.

Every note is a triple of integer milliseconds:

    (column, start_ms, end_ms)

- column: 0, 1, 2, 3 (4 keys only)
- start_ms: absolute song time at original 1.0x rate
- end_ms: hold/roll release, or -1 for a tap
- Both start and end are scaled by rate with floor(), as expected by XDC1.
- The LN toggle can set end_ms to -1 without changing a chart's source.
- Rows are sorted by (start_ms, column).
- Negative start times due to OFFSET are preserved rather than clipped.
  The future XDC1 subprocess adapter must shift **all** times so that
  XDC1 receives nonnegative note heads, and restore the time axis later.
  A real hold end equal to -1 ms is explicitly rejected, to avoid being
  mistaken for a tap. The same guard exists after rate scaling.

## Format-specific rules

- .osu: reconstructs holds from the parsed object type 128, preserving
  the existing data["notes"] array of two-field tuples for 1.1.1.
- .sm: pairs type 2 (hold head) and type 4 (roll head) with type 3
  (release) in the same column, including across measure boundaries.
- .ssc: follows the same note rules but uses the **selected chart's**
  effective BPMs, STOPS, DELAYS, WARPS and OFFSET overrides.
- Type M (mine), L (lift), F (fake) are not modeled as playable
  keystrokes by XDC1 and are ignored. Unrecognized symbols fail explicitly.
- Orphan or unclosed holds, overlapping holds and malformed rows fail
  instead of silently contributing inaccurate difficulty estimates.
- Timing supports BPMS, STOPS, DELAYS and OFFSET through the existing
  beat-to-seconds converter. WARPS are still **not supported** and
  raise NotImplementedError instead of estimating the timing.
- All StepMania measures currently assume four beats, as before.
  Nonstandard time signatures are a separate future parser task.

## Backward compatibility

The existing convert_stepmania_chart() and load_osu()["notes"] paths
still produce (column, start_ms) pairs for the old calculator. This
change does not affect the normal UI, bridge polling, difficulty,
nomenclature labels or image assets.

## Milestone A complete: native XDC1 engine and Python adapter

- Upstream C++ source: xdc1/xdc1.cpp, copied without algorithm changes
  from TheBagelOfMan/xdc1 commit bc27ad77c1f94ddd871e9fba47ac69f56834da62.
- xdc1/LICENSE preserves its MIT copyright and redistribution notice.
- src/dan_scale.py is the original Daniel 2.x points-to-Dan calibration.
- src/xdc1_adapter.py accepts 4K triples, runs XDC1 with --graph through
  a subprocess, checks JSON/error handling, restores negative time-axis
  offsets, and returns the same calibration and seven skillsets as Daniel 2.x.
- The adapter is **not connected to src/daniel_etterna.py** yet; this
  deliberately leaves the current 1.1.1 app, bridge and UI unchanged.
- The engine output is not yet packaged inside the regular .exe build;
  packaging is deferred until the new UI path is ready.

### Build and test on Windows

In CMD, from the repository root:

    build_xdc1.bat
    py -m unittest discover -s tests -p "test_xdc1_adapter.py" -v
    py -m unittest discover -s tests -p "test_chart_normalization.py" -v

The script finds Visual Studio 2026 or 2022 (with Desktop development
with C++) and produces src/xdc1.exe. You can point to a custom compatible
executable using XDC1_BIN_PATH.

### Build and test on Linux

    g++ -O2 -std=c++17 xdc1/xdc1.cpp -o src/xdc1
    python3 -m unittest discover -s tests -p "test_xdc1_adapter.py" -v
    python3 -m unittest discover -s tests -p "test_chart_normalization.py" -v

GitHub Actions checks both operating systems on every new commit.
Integration tests compare XDC1 subprocess JSON with a direct invocation
of the same native binary and verify the Dan conversion and graph.
These tests demonstrate correct input/output integration; they do not
yet prove performance on real Etterna chart libraries or benchmark
agreement with Dan labels.

### Python interface (for the next development phase)

    import chart_loader
    import xdc1_adapter

    data = chart_loader.load_chart_file("song.ssc")
    selected = data["charts"][0]  # replace with Etterna's selected chart
    result = xdc1_adapter.analyze_chart(
        data, selected, rate=1.0, include_long_notes=True
    )
    dan = result["rating"]
    skillsets = result["skillsets"]
    grid_ms = result["grid"]
    strain = result["strain_rested"]

The adapter accepts integer millisecond triples; it uses the native
engine's graph strain rather than changing the existing graph renderer.

## Experimental engine selector in Options > General

The difficulty-engine section is an expandable accordion below Keybinds.
It provides Legacy (default) and XDC1, with localized English/Spanish
descriptions. General is scrollable so expanded settings cannot obscure
Save/Cancel on smaller windows.

- Engine selection is persisted under difficulty_engine in config.json
  (config version 9); existing 1.1.1 configurations migrate to Legacy.
- Save applies the new engine for the same selected song. Cancel does not.
- XDC1 selection requires an installed/compiled binary; Save reports a
  localized error if the engine cannot be found.
- The Legacy path remains algorithm.calculate_notes(...) and Etterna's
  native MSD. XDC1 uses chart_loader.normalize_chart_notes(...), applies
  the live Etterna rate, executes the native engine, converts results to
  original Daniel 2.x Dan boundaries, and preserves Skins/DP/badge
  formatting. The statistics row uses XDC1's seven skillsets and does
  not label their ratings as Etterna MSD.
- The existing strain graph is reused with proximity fade and smoothing.
  This requires chart-specific in-game validation before releasing 2.0.
- WARPS, nonstandard time signatures, and other parser limitations
  remain unsupported in the new engine; Legacy behavior is unchanged.
- XDC1 is presently enabled for development testing; the application
  retains version 1.1.1 until release validation.

### Windows build (both motors packaged in one EXE)

The 2.0-dev build_windows.bat first runs build_xdc1.bat, then generates
the Reform badge PNGs and builds dist/DanielEtterna.exe using PyInstaller.
It packages src/xdc1.exe under the PyInstaller extraction root, alongside
the SVG/PNG/WebP badge assets. Visual Studio Build Tools 2022 or 2026
(with C++) must be installed to compile the engine.

If building manually in CMD, first run:

    build_xdc1.bat
    py -m pip install -r requirements.txt
    py scripts\prepare_reform_png.py

Then invoke PyInstaller using the same existing options **plus**:

    --add-data "src\xdc1.exe;."

Omitting that resource will prevent XDC1 from working in the onefile
version even if the Python-source build worked correctly.
